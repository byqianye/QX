# 项目维护规则

更新时间：2026-09-08

## 唯一状态台账

[PROJECT-STATUS.md](PROJECT-STATUS.md) 是以后持续更新的唯一任务记录。每个 Goal 或专项任务都要在同一文档追加一条记录，至少包含：

- 日期和任务名称
- 状态：`planned`、`in_progress`、`verified`、`blocked` 或 `abandoned`
- 依赖和范围
- 修改文件
- 验证命令及结果
- 证据文件
- 未完成事项和风险

详细报告可以继续放在 `docs/reports/`，但报告完成后必须回链到状态台账。不要另建平行的“最新状态”文件。

## 每次任务的工作顺序

1. 读取 `AGENTS.md`、本文件和 `PROJECT-STATUS.md`。
2. 执行 `git status --short`，保留已有未提交修改。
3. 阅读当前 Goal 直接相关的代码、Spike/报告和测试。
4. 先写可检查的验收标准，再做最小修改。
5. 运行与改动匹配的测试；核心逻辑、RPC、源适配和播放改动要补行为测试。
6. 更新 `PROJECT-STATUS.md`，列出真实证据和仍未完成的事项。
7. 检查 `git diff --check`，确认没有临时文件或无关重构。

## 源适配的尺度

源状态分开记录：

| 状态 | 含义 |
| --- | --- |
| `适配正确` | 响应格式、鉴权边界和转换规则有合同或真实响应证据 |
| `当前可达` | 最近一次请求未超时且返回可解析数据 |
| `短测可播` | 真实 Tauri 有解码帧并持续播放短时长 |
| `稳定验收` | 电影和剧集样本均达到项目规定的连续播放门槛 |
| `失败/不支持` | 记录明确错误或协议超出当前边界 |

临时的 403、404、522、WAF、滑块和网络超时不自动推导新协议。先复测、记录响应，再决定是否修改 Rust 适配层。禁止执行远程 JS/DEX/JAR，禁止绕过验证码、DRM 或访问控制。

## 代码和构建维护

- Rust 适配层的入口、错误码、取消、超时和资源边界优先保持在 `src-tauri/src/`；不要把同一协议复制到 renderer。
- 最小 Tauri 包保持 `src-tauri/tauri.conf.json` 的 `bundle.resources` 为空，不引入外部运行时。
- 新增窗口权限时同步更新 `src-tauri/capabilities/default.json` 和权限测试。
- 修改 `package.json` 脚本时同步更新 [BUILD.md](BUILD.md)；命令名称以 `package.json` 为唯一事实来源。
- 生成的 `dist/`、`release/`、`target/` 和 `artifacts/` 只用于验证，不作为业务输入。

## 完成定义

一个任务只有在代码、测试、文档和状态台账都更新后才算完成。真实源或真实 Windows 环境缺失时，标记准确的阻塞范围，不用本地 fixture 的绿色结果替代线上结论。
